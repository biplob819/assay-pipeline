# S3.1 acceptance criteria

**GRD-01** Empty input, unparseable text, and any literal LIMIT or OFFSET that is not an integer in range (LIMIT ≥ 1, OFFSET ≥ 0; decimals and NULL included) are `parse_error` (a non-literal outer LIMIT is replaced by the cap, GRD-04), several statements (including ones hidden after comments) are `multiple_statements`, every non-SELECT statement in the corpus is `not_select`, and recursive CTEs are `recursive_cte`.
**GRD-02** Every table reference is resolved per scope: restricted, qualified and misspelled tables are `table_not_allowed` wherever they appear (joins, unions, subqueries, EXISTS, nested CTEs out of scope), a CTE named like a view is `cte_shadows_view`, and a string-literal table is `file_reference`.
**GRD-03** Table functions, any function outside the allow-list, and DuckDB keyword functions written as bare columns (`user`, `current_catalog`, …) are `function_not_allowed`, catalog schemas and catalog-named tables are `catalog_access`, casts to non-scalar types are refused; allowed functions and SELECT grammar (CASE, EXISTS, AND/OR, arithmetic, IN, BETWEEN, LIKE, FROM-first) pass.
**GRD-04** The outer LIMIT is rewritten to the smaller of the existing literal and 1,000 (1,000 for a non-literal or absent limit, set operations included), and inner limits cannot raise it.
**GRD-05** Only the comment-free re-rendered SQL is ever executed, it re-checks to the identical decision, a blocked decision never reaches the connection, and the guard never raises on any input (fuzzed).
**GRD-06** The known blow-up classes of D-28 are refused before DuckDB sees them, however they are named: over-size or over-deep statements, CTE fan-out (more than 16 tables after expansion), more than 4 nested derived tables, lateral column-alias chains (any cross-reference between select expressions of one SELECT), and string growth (any output value built from more than 64 source values, through CTEs, derived tables and set operations, with column-list and `* REPLACE`/`* RENAME` renaming refused, or a `||` chain of more than 8 operands); ordinary one-step aliases in WHERE, GROUP BY, HAVING and ORDER BY pass; an allowed query running past the timeout is interrupted and reported as `timeout`; and the hard availability guarantee is S3.3's child process (deadline and memory cap), as D-28 states.
**GRD-07** Every database error reaches the model only as one of the generic messages, so no table name, column suggestion or database text leaks, and a restricted canary never appears in any text the model is given.
**GRD-08** The corpus (sqlglot pinned below 31) holds at least 80 blocked statements covering every reason code with its exact expected reason and at least 40 allowed statements whose renderings run on DuckDB, and a property test shows any composition containing a denied fragment is blocked.
**GRD-09** The model sees at most 50 rows and never more than 6,000 characters (headers and footer included) plus the total row count; each cell is capped and escaped (every line-boundary character, `|`, `[`, `\`), so data cannot forge a row, a column or the `[result]` footer; fetching is row by row and stops at the row limit or the byte budget; and exactly the fetched rows are hashed into `result_sha256`.

**GRD-10** (OWNER D-40, hand-read finding 3 and 1) Every D-28 resource bound (node count and depth, tables after CTE expansion, nested derived tables, lateral aliases, value growth and the renaming that would hide it, `||` chains, a column in a SELECT with no FROM) blocks as `too_complex` when it is the first failing check (the bounds run before the grammar walk, so they also protect it), while non-SELECT statements, and non-SELECT grammar within the bounds, stay `not_select`; audit lines and anchors are written as format 1.1, a 1.0 line naming `too_complex` is refused, a 1.0 log still verifies and resumes with 1.1 lines; snapshots and run records stay 1.0. A capped result's footer is `[result] N shown of at least M rows (row or size limit reached)`; the scorer counts this footer and the pre-0.1.2 one as capped, and never a cell that contains either phrase.

**GRD-11** (OWNER D-43, hand-read of main-2026-11-18) An aggregate's `FILTER (WHERE ...)` and one `GROUP BY ROLLUP(...)` of at most 8 groupings, beside plain grouping columns, are allowed, and the agents' refused queries from that run now pass the guard and give the right numbers on DuckDB. A FILTER on a non-aggregate or with a window, a ROLLUP outside GROUP BY or beside CUBE, `CUBE`, `GROUPING SETS`, `PIVOT`, `QUALIFY`, window functions and non-scalar casts block as `syntax_not_allowed`; a ROLLUP of 9 or more groupings, or a second ROLLUP in the same GROUP BY, blocks as `too_complex`; `ROLLUP(*)` blocks as `syntax_not_allowed`; a restricted table, table function, keyword function or catalog read inside a FILTER or ROLLUP blocks with its own reason; a write or command anywhere (`SELECT ... INTO`, a DML CTE, `FOR UPDATE`, also behind shallower refused syntax) is checked first and stays `not_select`; a non-SELECT root stays `not_select`. Audit format 1.2 carries `syntax_not_allowed` and a 1.1 line cannot; 1.0 and 1.1 logs still verify and resume.

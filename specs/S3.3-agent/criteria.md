# S3.3 acceptance criteria

**AGT-01** `QueryTool` checks SQL with the guard in-process, runs only allowed SQL in a child process killed at the timeout plus a short grace (address space capped where the OS allows), returns generic messages for blocks, timeouts and crashes, and writes an audit line in a `finally` block for every call, even when the tool itself raises.
**AGT-02** The Claude Sonnet 5.5 agent uses the Anthropic Messages API with one strict native tool, automatic tool choice, a cached system prompt, no sampling parameters and no refusal fallbacks; thinking and tool calls go back unchanged, a turn's tool results go back in one message, and a refusal ends the trial as a refusal.
**AGT-03** The GPT-6.1 Sol agent uses the OpenAI Responses API with one strict function tool, instructions, reasoning effort and an output cap; function calls are answered with function_call_output items, and refusal content or a content filter ends the trial as a refusal.
**AGT-04** The system prompt states the behaviour rules, every approved view with its columns, the answer format with SQL lines and the snapshot id, and a deterministic prompt canary distinct from the embargo canaries.
**AGT-05** A trial stops at 8 tool calls and asks for a final answer, caps the answer at 8,000 characters, records malformed and unknown tool calls without running them, leaves question, query and answer lines in a verified audit log, and records an EvalKit trajectory with violations and cost.
**AGT-06** The agent package never imports the pipeline and opens DuckDB only in `agent/connection.py` (boundary gate and a test).
**AGT-07** `assay ask` asks one agent live with its key (refusing clearly without one) or replays a recording made with `--record`; responses are validated against the SDKs' own types, and a replay reproduces the trajectory and audit lines without the network, including replays of real recorded responses from both providers, which never hold the echoed system prompt or a canary; a provider failure ends the trial as `transport`, audited.

**AGT-08** (OWNER D-40, hand-read finding 2) When any approved view has a `flags` column, the system prompt says `flags` is a list of quality-rule ids, never text, and gives `length(flags) > 0` and `contains(CAST(flags AS VARCHAR), 'QC5')` as ways to test it; both pass the guard. A views config without `flags` gets no such line.

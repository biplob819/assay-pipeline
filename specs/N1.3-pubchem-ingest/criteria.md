# N1.3 acceptance criteria

**PUB-01** AIDs are listed for the configured gene symbol, and only AIDs whose summary lists the configured UniProt accession are kept (others dropped as `target_not_configured`, RefSeq-only targets included as a stated limit); within kept AIDs, rows for other targets are dropped as `other_target`.
**PUB-02** AIDs whose depositor is excluded (ChEMBL) are dropped as `chembl_deposited_aid` and AIDs that ChEMBL imported (ChEMBL source 7, paged, `493040_69` read as 493040) as `chembl_imported_aid`; every drop is a `Drop` in the ledger, and dropped AIDs never have their data fetched.
**PUB-03** The concise table of each kept AID is fetched and checked before caching; only rows whose activity name is the configured type are kept, with the micromolar value string exactly as sent (cells must be strings), a record id `AID:SID:n` unique to every row (rows without a positive-integer SID dropped as `no_sid`), the depositor and the PubMed id.
**PUB-04** Structures (SMILES, InChIKey) are fetched in batches for the CIDs of kept rows only; rows without a positive-integer CID or a structure (left out, sent without SMILES or InChIKey, or a `PUGREST.NotFound` batch) are dropped with a reason, never stopping the ingest.
**PUB-05** Requests are paced under five per second (the config requires fewer than 5), `PUGREST.ServerBusy` and other transient errors back off and retry, a failed run resumes without re-fetching and ends with the same cache bytes as a clean run, a complete release is a no-op until `--new-release`, the release is the UTC date with numerically ordered suffixes, and a changed config or depositor ledger is refused on resume and on read.
**PUB-06** `depositor_terms.yaml` is a strict ledger (case-insensitively unique names, real booleans only, licence, attribution, https evidence, checked date); ChEMBL deposits are dropped whatever the config; rows from depositors not listed or listed with `keep: false` are dropped as `depositor_not_cleared` without fetching their data.

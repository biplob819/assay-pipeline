# W0.1 acceptance criteria

**HAR-01** `uv sync --locked` installs the project on Python 3.11–3.15; `assay --version` prints the installed package version and `assay` with no command prints help and exits 0; the import package is `assay_pipeline` and the distribution `assay-pipeline`; the licence is MIT; `.gitattributes` forces LF; `.env` files are ignored.
**HAR-02** `ci.yml` runs ruff check and format, pyright, pytest, the secret scan, graph eligibility, the gate self-test and `uv build` on every push and pull request, on ubuntu, macOS and Windows with Python 3.11, 3.12 and 3.13, with actions pinned by commit SHA, one `contents: read` permissions block and no secrets.
**HAR-03** `verify_graph_eligibility.py` fails on a cycle, an unknown dependency and a node building ahead of a dependency, and passes on the live graph; its self-test passes.
**HAR-04** `node_start.py` refuses a node whose dependencies are not green, whose spec, criteria or tasks are missing, that has several spec folders, or whose criteria lack a `**CAP-ID** text` line for any capability row; check-only mode writes nothing.
**HAR-05** `node_converge.py` runs exactly the 13 gates of Tech Spec §11.6 in order and reports all of them after a failure; its self-test calls the real gate functions and every gate fails naming its planted defect, with `uv` required to be present. The boundary gate implements both halves of the D-25 boundary policy as written there — the static lint (every listed import, name, attribute, binding and DuckDB rule) and the runtime import check — each rule with a plant; clean agent and pipeline code passes; and D-25 states what the gate does not cover.
**HAR-06** `graph.md` has the 21 nodes and edges of Tech Spec §11.2; `catalog.tsv` has exactly the 128 rows of §11.4 (id, node and note, in order) and round-trips byte-identically; `decisions.md` holds D-1..D-26 with OWNER D-11, D-12, D-13, D-18, D-20, D-21, D-22 and D-23; lessons, changelog and the spend ledger exist; `status.py` prints every node and one node's rows, deterministically.
**HAR-07** The secret scan detects each supported key format, lists files NUL-separated (non-ASCII names included) and finds nothing in the live repo; `.env`, `.env.*`, `.leakguard` and `Portfolio notes.md` are git-ignored; private words are kept out exactly as D-25 describes: the leak guard reads them only from `.leakguard`, checks staged blobs, paths and commit messages through installed hooks and every publishable file and path through a local test, with the listed decodings and foldings, each proven necessary by a mutation test.

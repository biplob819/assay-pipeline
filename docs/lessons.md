# Lessons

Numbered L-n. Each lesson names the failure, the rule it produced, and where that rule is enforced. EvalKit's lessons (`~/EvalKit/docs/lessons.md`, L-1 to L-39) are required reading before each node; the ones below are carried over because this build repeats their conditions.

| ID | Lesson | Rule | Enforced by |
| --- | --- | --- | --- |
| L-1 | A gate that has never failed is a gate nobody has checked (EvalKit L-1, from Kova) | Every gate ships a `--self-test` that feeds it bad input and requires the defect to be named in the output | `node_converge.py --self-test`, `tests/harness/test_node_converge.py` |
| L-2 | Proofs can name a test that only appears in a comment, a string or a skipped function (EvalKit L-2) | Proofs resolve through `ast` to a real, unskipped `def test_*` under `tests/`; `logical` can never be n/a | `node_converge.proof_problems` |
| L-3 | Background verifiers that share the project venv rebuild it mid-converge (EvalKit L-15) | Verifiers run with `UV_PROJECT_ENVIRONMENT` pointing at a private scratch directory | verifier prompt template |
| L-4 | Scripted text edits can silently match nothing (EvalKit L-11) | Every scripted edit asserts its match count before writing | builder practice |
| L-5 | Canaries written inside injection text score an agent that quotes the attack as leaking (EvalKit L-33) | Canaries live only in restricted rows and the system prompt; a test checks no prompt or planted text contains one | ATK-06 |
| L-6 | Every unit test passed while the published headline was wrong, because each step was tested alone (EvalKit L-37) | Before publishing, read a sample of real answers and audit lines by hand | REL-05 |
| L-7 | Docs described in the present tense things that were not yet true (EvalKit L-16) | Docs say what is true now and name the node that makes the rest true | verifier checklist |
| L-8 | W0.1 verifier: the boundary gate only read absolute `import X` names, so `from assay import agent`, `from ..agent import x`, aliased DuckDB and indirect `connect` references all passed | Resolve every import to its full module name (relative imports against the file's package; `from X import Y` as `X.Y`) and track aliases; a dynamic import of a non-literal name fails | `node_converge.boundary_problems`, `BOUNDARY_PLANTS` |
| L-9 | W0.1 verifier: the self-test exercised helpers with their own commands, so replacing a gate with an always-PASS stub still passed it, and a missing `uv` passed gate 11 | A self-test calls the exact functions `GATES` runs, requires the planted defect's name in the detail, and checks the tool exists before planting | `node_converge.self_test`, `test_self_test_shows_every_gate_can_fail` |
| L-10 | W0.1 verifier: a test written to keep a word out of the repo contained the word, and it scanned only one file per basename, case-sensitively | A leak guard stores hashes, not the words, and scans every file git would publish (`git ls-files --cached --others --exclude-standard`), case-insensitively | `test_portfolio_notes_stay_out_of_public_repo` |
| L-11 | W0.1 verifier: "criteria.md names every capability" was a substring check, so a bare mention or a longer id counted | A criterion is a `**CAP-ID** text` line, matched in one shared helper | `harness_lib.criteria_missing` |
| L-12 | W0.1 verifier pass 2: after the scanner learned every pass-1 form, about 20 new dynamic-Python forms still passed | A static check over a dynamic language is made complete by banning the dynamic constructs in the protected zones, not by recognising each form; runtime tests prove the real permission | `node_converge.zone_problems`, `test_boundary_policy_is_closed_by_prohibition` |
| L-13 | W0.1 verifier pass 2: an unsalted sha256 of a common word was guessed on the first try, and file mtimes made the freshness gate fail on every fresh clone yet pass after a bare `touch` | Never commit a reversible stand-in for a secret; keep it in a git-ignored file. Judge "changed" by git content and commit times, never raw mtimes | `scripts/leak_guard.py`, `node_converge.freshness_problem` |
| L-14 | W0.1 verifier pass 3: a self-test made of samples that an earlier layer already catches cannot tell whether a later layer works, and a 'changed' check built on file times can be fooled by a backdated copy | Give every layer a sample only it catches, and prove it with a mutation test that removes the layer; for working-tree files, judge change by content (dirty vs HEAD), not time | `test_leak_guard_self_test_fails_when_any_layer_is_removed`, `node_converge.freshness_problem` |
| L-15 | W0.1 verifier pass 4: after three rounds of tightening, the boundary lint still had bypasses, and a hook that scanned the working tree let staged content through | State what a check can and cannot catch instead of claiming completeness, pair a static lint with a runtime check, and make commit hooks read what git will actually commit (staged blobs, paths, the message) | D-25, `runtime_boundary_problems`, `leak_guard.staged_hits` |
| L-16 | N1.1 verifier: `\\d` in pydantic (Rust regex) patterns matches any Unicode digit, so `1.٠` passed as a schema version and `nq-٠٧` as an id | Every pattern uses `[0-9]`; a test feeds Arabic-Indic digits to every id and version field | `test_unicode_digits_are_rejected` |
| L-17 | N1.1 verifier: a dict subclass that blocks `__setitem__` cannot be deep-copied or pickled, because both rebuild through item assignment | Immutable containers define `__reduce__`, `__copy__` and `__deepcopy__` that rebuild through the constructor | `test_records_survive_deepcopy_pickle_and_deep_model_copy` |
